# Cheap complete DM read via MCP (card #735) — Spec

**Goal:** Give every MCP host three DM tools so a cell can take a
**cheap complete** unread batch (full bodies, typed fields, one call),
reply without a content-file dance, and fetch a thread — without
importing a cursor or a separate ack.

This is a spec. It does not change the live MCP server.

Pairs with #729 (why a cell does not SEE a DM). This card is what a
DM **costs** once awake. Not the delivery fix (#263).

## Measured (lab-ovh, 40-message window)

| form | size | ~tok | property |
|---|---|---|---|
| `mesh inbox --peek --json` | 70,604 B | ~17,651 | complete; must parse |
| `mesh inbox --peek` | 8,272 B | ~2,068 | affordable; **bodies truncated** (~160 chars/line) |
| content alone | 54,160 B | ~13,540 | irreducible meaning |
| envelope | 16,444 B | ~4,111 | **23%** of the complete read |

There is no cheap complete CLI read today. The price signal selects
`--peek` prose; that already cost 77 minutes on cursor-lin status
DM id=32049 (1,483 chars read as a 78-char preview).

MCP today: six tools (`search`, `add`, `describe`, `codegraph_query`,
`memory_navigate`, `timeline_navigate`). **DM tools: zero.** Every
read is bash + `--json` + a retyped parser (billed again).

## Mechanism: three tools, batch-shaped

Wire plain helpers in `mcp_server.py` (same pattern as
`_timeline_navigate`) and expose them on FastMCP. Identity /
gateway / token resolve the same way other mesh verbs do
(`--as` / `$SWARPH_SELF` / peer token file) — never ambient-consume
another peer's unread without an explicit self (#578 family).

### 1. `swarph_dm_unread()`

- Returns **all unread** DMs for the resolved self in **one** call.
- Each item: typed fields at minimum `id`, `from_node`, `to_node`,
  `kind`, `created_at`, `thread_id`, **`content` (FULL string)**.
- **No paging. No cursor. No next/previous/close.**
- Default: **peek semantics** (do not mark read). Consuming read is
  NOT the tool's job — see "ack" below.
- Envelope: prefer a **lean JSON schema** (drop null noise keys the
  gateway echoes) so the call is measurably cheaper than an equivalent
  `--json` window of the same messages. Content bytes stay intact.
- Cap: if unread count exceeds a hard safety ceiling (propose **100**),
  return the oldest N full bodies **plus** a loud top-level field
  `truncated_count` / `refused_silent_truncation: false` naming how many
  remain. Never silently drop. Never shorten a body to fit.

### 2. `swarph_dm_reply(id, text, kind="answer")`

- One call. Body is the `text` argument — **no content-file**.
- Routes by message id (existing `mesh reply` behaviour).
- Does **not** close board obligations (`board obligations close` stays
  the close act — #562).

### 3. `swarph_dm_thread(id)`

- Returns the conversation for that message / thread_id, full bodies.
- Same lean schema as unread.

### Hard exclusions (commander-confirmed)

| forbidden | why |
|---|---|
| `next` / `previous` / `close` | imports a **cursor** — hidden cross-turn state; LLM-worst; makes the 21:21-drain / 21:22-arrival miss systematic |
| separate `ack` verb | another forgettable act (assignment-without-dispatch shape). **Replying is the ack.** Anything still unacked keeps appearing in `dm_unread()`. |

Do not mark-read on `dm_unread()`. If a cell needs consume-on-read for
a PullSink ledger, that remains the CLI `mesh inbox` path (or a later
card). This card removes the incentive to read less; it does not
redefine monitor ACK.

## Summary: index vs filter, and how to pick a model

Commander asked whether a semantic AI summary could replace `--peek`
for long DMs. Answer lands on #585: the secretary is an **INDEX**, not
a filter.

| surface | policy |
|---|---|
| **Directed DMs via `dm_unread`** | **full bodies always** — a model summary must never *replace* the tool payload |
| **Optional index / channel bulk** | may summarise **only** if chosen by `swarph bench`, not by preference |

Lab 07:0xZ: commander shaped the can-fail as a **bench pack**. That
makes the summariser a **measured** choice (`swarph bench` already
caught one wrong model when price pointed the other way).

### Pack structure (`swarph bench validate` / `run`)

```
scenario   = a real DM (verbatim — never synthetic)
steps      = layered context + requirements (what the reading cell knows / owes)
injection  = IF message has thread_id, step PULLS thread text so the
             summary is scored on FOLLOW-THROUGH, not isolation
expected   = target output (payload-retention shaped — below)
```

The injection clause is load-bearing: a one-message summariser cannot
know that "acked 32200" carries an obligation forward. Continuity is
what failed last night; the pack must test it.

### Scorer = payload retention, NOT summary quality

Binary / deterministic. Optimising "good prose" drops ids and
reproduces the polished dismissal that cost 77 minutes.

| check | rule |
|---|---|
| RETAINED? | every card id, obligation id, PR number, thread_id |
| RETAINED? | the ASK (question / blocker / request) |
| RETAINED? | any REFUSAL or correction |
| COMPRESSED? | ratio vs source — returning the input unchanged **FAILS** |

Winner = high retention + high compression. Unchanged input fails
compression; aggressive compression fails retention.

### Fixture 1 — message 32049 (required)

1,483-char cursor-lin status. Expected: grouped by what it demands of
the **reader** (owed / asks / refused / notice / blocked), ids
verbatim, refusal on its own line, "BLOCKED, no action" kept. ~10 lines
vs 1,483 chars.

>>> If a candidate renders "cursor-lin progress update", REJECT — that
is the message's own first line and why it was skipped. <<<

### Fixtures 2 and 3 — real traffic only

- **Threaded** DM (`thread_id` present): assert obligation from the
  **prior** turn survives injection.
- **Short ack** ("acked 32124, holding"): assert the model does **not**
  pad; expanding a ~40-char ack into a paragraph fails (inverted axis).

### Context-length warning

Bench rankings invert with context size (droplet 2026-07-31). Pack
**must** use real DM lengths (32049 = 1,483 chars; lab briefs 3–5k;
full `--json` window ~17.6k tok). Snippet benches predict nothing.

### Build adds (both in `swarph_cli/bench/backends.py`)

1. **Wire `SubscriptionBackend.call_fn`** to services layer:
   `POST http://100.64.189.91:{port}/delegate` with Bearer, return text.
   Docstring already left this seam to the caller (decision #3) —
   supplying `call_fn` is intended, not a violation.
2. **Add a local OpenAI-compatible backend** (name may be `OllamaBackend`):
   `POST {base}/v1/chat/completions` — **not** `/api/generate`.
   gpu-wsl ollama already exposes `/v1/models` (rc=200). One surface then
   serves every local tag, including a pulled Mistral open-weights tag,
   with no Mistral SDK and no API key. Base URL from **env** (default
   gpu-wsl tailnet as DATA, not a forever hardcode —
   [[feedback_a_remedy_has_an_expiry_date]]).

**Metered Mistral stays spend-gated.** `MeteredMistralBackend` takes
`api_key` only — no `base_url` seam. Local Mistral ≠ that class; it
rides the OpenAI-compatible local backend.

**`num_ctx` is mandatory on every local call.** Ollama defaults to 2048
unless Modelfile/request overrides — a 7B with a 32k weight file still
truncates at 2048. The pack MUST set `num_ctx` explicitly and the run
MUST record the value used, or every local arm silently scores the
**window** (two-states-one-rendering, same family as gemini health-200 /
delegate-503).

**CAN-FAIL each backend:** dead subscription port → per-model failure
**reported**, not silent skip; missing local tag → same. Silent drop
reproduces this card's defect.

**VRAM:** gpu-wsl ollama is shared. Ask gpu-wsl for constraint before
loading 7B / an extra mistral tag ([[feedback_gpu_wsl_vram_coordination]])
— not just retry; not assumed unilaterally.

## Accept

1. `swarph_dm_unread()` fixture: full bodies byte-equal; no truncation.
2. Cost measurably less than equivalent `--json` window (lean envelope).
3. Truncating bodies to save tokens = rebuilt defect.
4. No next/prev/close/ack in tool schema.
5. README / guide mention the three DM tools once.
6. Summariser either absent or selected by bench pack (fixtures 1–3,
   retention scorer, real lengths) on the $0 roster above.
7. Subscription + Ollama backends: can-fails green (dead port / missing
   tag report per-model, never silent skip).
